The core verdict

Engineering quality is world-class; governance and meta-process are the weak flank. The same BuildFlow-daemon failure class has 6 open blockers and 5+ documented regressions, master ran red for 9 days once with no branch protection to catch it, and facts that live in 5 documents by hand (component and golden counts) have already drifted. The library outran its own bookkeeping.

The core move

Convert tribal knowledge into machine-checked single sources: generated counts, tracked git hooks, a post-tag consumer-compile smoke test, and one dedicated upstream BuildFlow sprint. Then spend the freed attention on depth testing (axe-core, HTML validation, mutation testing) rather than more breadth.

01Self-Review Answers

Forgot

1. What did we forget?

governance surface

No SECURITY.md, no CODEOWNERS, no issue templates, no branch protection (TODO #123). We shipped a "v2 behavior set" (v1.8.2 default flips) on a v1 module path and never wrote down when the /v2 path migration happens. And there is a 15 MB compiled demo binary sitting untracked in the repo root (./demo, built 2026-09-09), the exact incident class AGENTS.md documents for visualtest/shots.

Stupid

2. What is stupid that we do anyway?

buildflow daemon · manual counts

We fight the BuildFlow daemon with per-repo guards (check-lint-config.sh, check-css-minified.sh, TestGolangciDisabledLinters) instead of fixing the daemon. Six blockers (#93, #107, #108, #124, #125, #126) all live in one other repo. Also: component and golden counts are hand-maintained in README, FEATURES, ROADMAP, AGENTS, and SKILL, which guarantees drift.

Drift

3. and 5. What could be better? Did the docs lie?

docs counts

Yes, in small verifiable ways: ROADMAP claims 175 HTML golden baselines; disk holds 242 .golden files. AGENTS.md says "102 golden files" from an older era. The visual-golden count (125) is correct. Individually trivial; as a pattern it means every prose number is suspect.

Fix Generate counts from the tree into one JSON and template everywhere else (idea #32).
Ghosts

7. Ghost systems?

guards that guard nothing

TestSkillComponentCount is an informational guard that never fails: a ghost guard consuming CI time while protecting nothing. Either gate it or delete it (idea #33). Orphaned golden files (no test referencing them) are a structural ghost risk as the suite grows (idea #54).

Scope

8. Scope creep trap?

121 components and growing

Mild but real. We have an excellent mechanism for rejecting categories formally (ADR-0021 headless, ADR-0033 Web Components, container-query strategy doc) and we should use it more, plus run a deprecation sweep: post-ADR-0017, do Popover and Dropdown both earn their keep? (idea #82).

Split brains

10. Split brains found?

see section 02

Six, all small: prose counts in five docs, two pre-commit entry paths, hand-edited README version badge vs utils.Version, three theme-preset CSS files hand-written, per-component typed request parsers vs a generic decoder, and the untracked root binary. Full list below.

Tests

11. How are we doing on tests?

breadth excellent, depth next

Breadth is elite: 242 HTML goldens, 125 pixel goldens, dual-transport browser e2e, fuzz, benchmarks, six compliance scanners, drift guards. The depth gaps: no axe-core a11y audit in the browser harness, no HTML validation, no mutation testing to prove the tests bite, no determinism gate, Chromium-only visual coverage. Category D is fourteen ideas on exactly this.

Strengths to Preserve

+
Incident-driven hardening Every guard maps to a real incident (release-checklist doc). Keep that discipline while fixing causes upstream.
+
Dual-transport wire design One spec, two dialects, browser-proven. This is genuinely differentiated; guard it with the D3 rule.
+
Platform-first components dialog, popover, details, scroll-snap, container queries: less JS than any peer library. The rejection ADRs (0021, 0033) are as valuable as the adoptions.
+
Compliance scanners as tests Dark mode, RTL, motion-reduce, coarse-pointer, container queries: conventions enforced by CI, not review vigilance.
+
Documented honesty 26 status reports, annotated and archived; runtime facts docs pinned by contract tests. Rare and worth protecting.
