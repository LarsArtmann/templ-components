Historical narratives extracted from `AGENTS.md` (2026-09-15, AGENTS.md

**Reconciled at v0.18.1:** commit 73395d9 expanded to 67 linters but left `golangci-lint run` failing (187 findings, CI would have gone red on first push). The config now uses an explicit depguard allow-list (the `$module` token did not resolve — use literal `github.com/larsartmann/templ-components` + the three runtime deps), extends `varnamelen`/`mnd` ignore lists, and excludes test files from `err113`/`makezero`/`varnamelen`/`gocheckcompilerdirectives`. If you add a linter, run `golangci-lint run` to 0 findings before committing.

**Lint per file, not per session (2026-09-08 lesson):** after writing any new `.go` file, immediately run `(cd <module> && golangci-lint run ./...)`. The 67-linter config makes "verify at the end" expensive — one session burned 3 extra full-verify cycles (19+12+5+3 findings) on findings that a per-file lint would have caught at authoring time.

**Guard tests must fail loud, never skip on missing fixtures:** a drift guard that `t.Skipf`s when its fixture (go.work, CSS file, etc.) is "not found" silently passes forever while protecting nothing — the `../..` vs `..` path bug in `TestGoWorkDirectiveMatchesRootGoMod` (utils is a sub-module; `..` IS the repo root) shipped a guard that never ran. Guards that own a fixture must `t.Fatalf` when it is absent.

**`.golangci.yml` regression root cause (identified 2026-07-28, T1):** The 3 disabled linters re-entered the enable list **5 times** across sessions. Root cause: the AI agent's working tree holds a stale `.golangci.yml`, and broad `git add` for docs work silently stages the stale file. BuildFlow's pre-commit hook has a 60s budget and does NOT run `go test ./...`, so `TestGolangciDisabledLinters` only fires in CI, not at commit time. **Prevention (3 layers):** (1) `TestGolangciDisabledLinters` in `utils/lint_config_test.go` catches in CI via `go test ./...`; (2) `scripts/check-lint-config.sh` is a <50ms standalone grep guard wired into `.git/hooks/pre-commit` BEFORE BuildFlow runs; (3) CI step "Lint-config guard" in `.github/workflows/ci.yaml` runs the script before `golangci-lint` even installs. If you must modify `.golangci.yml`, run `scripts/check-lint-config.sh` to verify.

**CI lint-lane masking (2026-09-17 lesson):** the Lint job's sequential per-module loop aborts at the first failing module, so one defect hides the next — a utils `wsl_v5` failure masked a visualtest `gocognit` violation for 3 consecutive red runs, and the visualtest lint lane itself had drifted out of `ci-repro.sh` (local "ALL STEPS PASSED" was a lie; fixed 2026-09-17 by adding the lane + fixing the finding via real decomposition, not a waiver). Two structural fixes pending: a drift-guard asserting ci.yaml's lint module set == ci-repro.sh's (TODO_LIST #243) and continue-past-failure + aggregate summary in the CI loop.
