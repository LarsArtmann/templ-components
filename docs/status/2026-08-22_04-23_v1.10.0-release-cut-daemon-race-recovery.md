## d) TOTALLY FUCKED UP (own goals, honest accounting)

1. **I created the race window that made the blemishes permanent.** Knowing the daemon exists (documented in AGENTS.md!) and having watched it commit the version bumps mid-script minutes earlier, I still ran the surgical tag-content repair (commit → delete tags → re-tag) through the **4-minute pre-commit hook without `--no-verify`**. The daemon committed my staged fixes with its own messages and pushed master + all 7 tags mid-hook. Tags went immutable before the corrected tree existed. The two tag blemishes (self-replace, stale CSS) are now **permanently published** — harmless (proven by consumer tests), but unfixable by the ecosystem's own rules. Correct move: `--no-verify` (I even used it for the later hardening commit and documented why), or pause the daemon, or do the repair as one fast, hook-free transaction.
2. **The aborted repair nearly caused local/remote tag divergence.** My sequence would have deleted local tags while the daemon was pushing them; only `set -e` aborting on "nothing to commit" (daemon had already taken my changes) prevented me from re-tagging locally at different commits than the remote. Saved by a side effect, not by design.
3. **I didn't pause the release when the first race was detected.** After spotting daemon commit `e982c1e` (version bumps committed mid-script _before_ my release commit), the right call was stop-and-assess; I continued and only investigated afterwards.

## e) WHAT WE SHOULD IMPROVE (structural)

1. **Make release.sh self-contained and hook-free:** it already runs the entire verify suite internally; its own `git commit`s should use `--no-verify`. The pre-commit hook adds nothing but the race window. This is the single highest-value fix.
2. **Pin step 8b to `$RELEASE_COMMIT`** (see b1) — one-line fix.
3. **Pause/lock the daemon during cuts** — either a BuildFlow feature (release lock file the daemon respects) or operationally (`systemctl --user stop buildflow`-style) before invoking release.sh. Fix lives in `larsartmann/buildflow`.
4. **Step 8b could also assert CSS freshness** (recompile to temp + `cmp` against committed artifacts) — I considered it, didn't implement.
5. **Daemon commit hygiene:** it steals staged changes and pushes without review, violating the house rule by construction. At minimum it should never push tags; ideally it should skip running when another git process holds the index (it caused a 4-minute lock queue this session too — two of my commits each idled ~4 min behind its preflight).
6. **`/mnt/buildcache` autofs is still dead** — every LSP diagnostic is noise; session after session burns attention on it. Environment fix (repin or repair the mount) keeps getting deferred.
7. **Review the ~87 auto-fixed lines** (b3) or add a policy excluding auto-fix-on-commit for release commits.
