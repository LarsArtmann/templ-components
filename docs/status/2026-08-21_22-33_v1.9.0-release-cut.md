## d) TOTALLY FUCKED UP (honest ledger)

1. **I ran the release script before pre-verifying its own preconditions in
   this environment.** The script had been "fixed" 7 days ago (d69e04b) but
   apparently never run since — I trusted the v1.8.4 precedent instead of a
   dry-run. First actual run died in verify. Cost: the messy recovery below.
2. **Mislabeled exit codes during diagnosis** — several `go build ... | head`
   pipelines where I read `head`'s exit (0) as build success, leading me down
   a wrong GOPRIVATE theory for several rounds. Caught by re-running with
   true exit capture. Lesson: never pipe a probe through `head` when the exit
   code is the datum.
3. **Misread annotated-tag hashes as commit hashes.** On checking remote tags
   I briefly declared an emergency ("tags point at different commits!") —
   annotated tag objects have their own SHA; they all peeled to `4951c07`.
   Self-corrected within one tool call, but a calmer first look
   (`git rev-parse tag^{commit}`) would have avoided the false alarm.
4. **Race-condition sloppiness with the auto-commit daemon.** The daemon
   committed my in-flight work THREE times mid-session (including the
   half-cut release as `4951c07`, then re-adding replaces as `c711fa7`), and
   later regressed two of my same-day fixes. I adapted (audit → keep →
   continue) but repeatedly had near-misses (a `git checkout --` on go.mod
   racing daemon state; staged-vs-worktree confusion mid-commit). The daemon
   is documented in AGENTS.md; I under-anticipated it. A lock/pause mechanism
   (or pausing it during release windows) would remove this entire risk
   class.
5. **The release commit body lacks the standard trailer block.** `4951c07`
   was daemon-authored from my half-run; its body carries good notes but not
   the `💘 Generated with Crush / Assisted-by` attribution, and the subject is
   `chore(release):` not the convention's `release:`. Immutable now (tagged,
   published) — cosmetic debt only.

## e) WHAT WE SHOULD IMPROVE (structural, ranked)

1. **Pause/lock the daemon during release cuts.** Highest value. This session
   had 3 daemon collisions and 2 daemon regressions. A `buildflow pause` (or
   even just a convention: cut releases with the daemon stopped) eliminates
   the class.
2. **Make the release script fail faster and self-test.** Ideas: `--dry-run`
   that stops after the version-file mutations (before verify) so ordering is
   testable; assert "script has exactly one `trap ... EXIT`" via shellcheck
   SC2064-adjacent custom check; a smoke test that runs the whole script
   against a fixture repo in CI.
3. **CI gate on the script.** The verify-before-strip fix is exactly the kind
   of change that rots back. A CI job that greps release.sh for strip-before-
   verify ordering (or runs the fixture smoke test) prevents regression.
4. **Website toolchain pinning.** The TS7/astro-check crash and html-validate
   enum break both came from loose `^` ranges on website deps. Pin majors
   (typescript, astro, html-validate) or add a renovate-style lockfile-only
   policy; the "bump website deps" commits have now broken CI twice (8/16 and
   8/21).
5. **pnpm/node parity.** `node` on PATH is a Bun shim lacking `node:sqlite`;
   pnpm needed `nix shell nixpkgs#nodejs_24`. Add nodejs to the flake
   devShell so website work doesn't require tribal knowledge.
6. **CSS Freshness gate should catch the daemon too.** The daemon's prettier
   pass un-minified app.css and broke the gate. Root fix belongs in BuildFlow
   (exclude generated/minified artifacts from formatting), noted here so it
   isn't lost.
