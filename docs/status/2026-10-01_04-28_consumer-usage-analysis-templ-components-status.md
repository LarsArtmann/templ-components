## e) WHAT WE SHOULD IMPROVE

1. **Treat CSS distribution as a first-class library concern, not a consumer problem.** All three consumers independently solve "how does Tailwind see the library's classes" and all three land on a different hack. That is a library defect expressed three ways.
2. **Stop relying on static-scan-invisible runtime class construction.** `GridColsAutoFit` (and any other runtime-assembled utility) is a design smell: it forces every consumer to safelist. Either emit a static class or ship the safelist.
3. **Never emit CSP-hostile inline styles from library components.** `style="--tc-sidebar-w:…"` breaks under strict CSP and silently forces consumers into CSS workarounds. Prefer a class or a nonce'd `<style>`.
4. **Make `AppShell` extensible** (boost/partial hooks, swap target, skip-link, theming var) or explicitly document that consumers who need those must roll their own — currently they discover it by divergence.
5. **Investigate why `errorpage` helpers go unused.** A library that provides `ErrorHandler`/`FromError`/`WriteError` while its most sophisticated consumer hand-rolls equivalents is either under-documented or under-capable. Find out which.
6. **Adopt cqrs-htmx's adoption-audit + divergence-register discipline** as a consumer-contract the library endorses and links.
7. **Correct grep hygiene:** always exclude `vendor/` when analyzing a consumer.
8. **Size sub-agent work to fit the deadline** (or don't offload it).
