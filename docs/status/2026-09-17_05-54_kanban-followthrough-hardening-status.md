## e) WHAT WE SHOULD IMPROVE

1. **Assertions against artifacts, never memory.** Every wrong marker (D2) came from writing
   what the markup "should" say. Read the rendered HTML (curl-equivalent, golden file, or the
   templ source) before writing an assertion.
2. **Window-greps are not evidence.** Enumerating constants requires the full type block
   (or the generated file). Prefer `sed -n '/type X string/,/^)/p'`-style whole-block reads
   for anything that will be written into a doc.
3. **Check the lint config before writing a new package.** One look at the visualtest lint
   setup would have front-loaded exhaustruct/noctx/forbidigo/funlen/mnd/varnamelen —
   D3's 3 rounds → 0.
4. **Reason about overflow before generating pixel goldens.** `overflow-x-auto` rows +
   fixed-width fixtures clip; decide column count from the fixture width first.
5. **visualtest/tools is not lint-enforced** — `siteshots` sits with pre-existing findings
   (err113/errcheck/forbidigo). Either add a visualtest lint lane to CI or document the
   non-enforcement; today it is ad-hoc (my smoke CLI got linted only because I chose to).
6. **Demo contract-marker cheat-sheet** — `data-tc-kanban` (not `-board`), `/health` is JSON,
   the csrf input markup, `PORT` override. One table in `docs/visual-testing.md` stops every
   future session re-deriving them (D2/D5).
7. **Demo/e2e endpoint implementations are twins that can drift.** `kanbanDemoState` and
   `kanbanE2EBoard` now implement the same add/reset/CSRF/same-origin contract twice. A
   shared builder or a comment cross-binding them (change one → change the other) would
   prevent silent divergence. Noticed this session; not acted on.
8. **The CSRF token is per-process.** Fine for a demo, but the "secure path" modeling has a
   ceiling — a per-session token store would model real apps (noted as future work, not
   promised anywhere).
9. **Plan template file.** The plan-authoring checklist now lives in AGENTS.md (memory);
   a `docs/planning/TEMPLATE.md` that plans copy would make the two checklist lines
   structural rather than recall-dependent.
