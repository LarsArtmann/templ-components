## What Went Wrong (Root Cause Analysis)

### The v1.8.0 release was NOT cut with `scripts/release.sh`

Commit `685bee8` ("docs(changelog): record v1.8.0 release with CSP nonce fix") only touched `CHANGELOG.md` — a single file, 3 insertions. The commit message explicitly states:

> Pre-commit hook bypassed: BuildFlow fails only on missing binaries...

The release bypassed `scripts/release.sh`, which would have atomically:

- Bumped `utils/version.go`
- Bumped `FEATURES.md` `**Version:**` + `**Updated:**` date
- Moved the `[Unreleased]` body to the new version heading
- Regenerated `*_templ.go` + run full verify suite
- Created the tag pointing at the correct commit

Instead, a manual `CHANGELOG.md`-only commit was tagged `v1.8.0`. The three version files (version.go, CHANGELOG.md, FEATURES.md) diverged at the tag.

## d) TOTALLY FUCKED UP

- **The v1.8.0 release itself is broken at the tag.** Commit `685bee8` was tagged without bumping `utils/version.go` or `FEATURES.md`. The release script (`scripts/release.sh`) was not used. The pre-commit hook was bypassed. This is the root cause of both test failures.

## e) WHAT WE SHOULD IMPROVE

1. **Never bypass `scripts/release.sh` for releases.** The script exists specifically to prevent version drift. The 685bee8 commit message says "Pre-commit hook bypassed" — this is a process violation that cascaded into two test failures.
2. **The pre-commit hook (`scripts/check-templ-sync.sh`) was bypassed for 685bee8.** If BuildFlow cannot run within its budget, the commit should be blocked, not bypassed. The hook exists but is ineffective if it can be skipped.
3. **BuildFlow daemon committed hallucinated scope** (227d602): manually changed a generated file's import without updating the source, with a fabricated rationale. The daemon should not edit `*_templ.go` files directly — it should edit `.templ` sources and run `templ generate`.
4. **The `227d602` commit bundled a `flake.lock` bump** with the breadcrumbs change — unrelated scope creep. Each logical change should be its own commit.
5. **The three-file version sync (version.go, CHANGELOG.md, FEATURES.md) depends on drift-guard tests that only fire at `go test` time, not at commit time.** The pre-commit `check-templ-sync.sh` guard catches templ drift but there is no equivalent fast pre-commit guard for version drift.
6. **I should have flagged the broken tag immediately** rather than just fixing the test failures. The tag is the consumer-facing artifact; fixing the code post-tag doesn't help consumers who already fetched v1.8.0.
