# ADR 0045: CSS Class Delivery for Module Consumers

## Date

2026-10-10

## Status

Accepted (decision). Implementation is **T2** in the extraction-backlog master
plan (`docs/planning/2026-10-10_06-06_extraction-backlog-pareto-master-plan.md`),
routed via TODO_LIST #399. Ships as tooling + docs (non-breaking) in a normal
minor release.

## Context

The library is consumed as a Go module; components emit Tailwind utility class
STRINGS in their `.templ`/`.go` sources. Tailwind generates utility CSS only
for class strings its scanner SEES at the consumer's CSS compile time — and
the Go module cache is outside every consumer's scan root. Each of three
audited consumers solved this independently (evidence E7, verified at source
2026-10-10):

| Consumer        | Mechanism                                                                                                                                                                                                                      | Source                                                                        |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------- |
| DiscordSync     | vendor-dir `@source`: `@source "../../../vendor/github.com/larsartmann/templ-components/**/*.templ"`                                                                                                                           | `internal/web/static/input.css:5`                                             |
| nsfw-classifier | curated per-file mirror (`third_party/css-scan/templ-components`) + `scripts/sync-css-scan-sources.sh` (resolves every sub-module from the build list via `go list -m`, copies from module cache, prunes)                      | `scripts/sync-css-scan-sources.sh`                                            |
| dnsblockd       | concatenated class inventory: `scripts/gen-library-classes.sh` concatenates library sources into ONE tracked `library-classes.txt`, `@source "."`-scanned next to `app.css`; atomic write + self-vendor via `go mod vendor -o` | `scripts/gen-library-classes.sh`, `internal/server/views/library-classes.txt` |

### The mechanism landscape is worse than "three ways" — the default-looking one is broken

`go mod vendor` + `@source "vendor/…"` LOOKS like the canonical answer, but
**Tailwind v4.3 never scans `.gitignore`d paths — not even paths listed
explicitly via `@source`** (dnsblockd's investigation, quoted in their
generator's header; Nix build sandboxes have no `.gitignore` at all, making
scans environment-dependent). DiscordSync's `vendor/` is gitignored
(`.gitignore:90`), so under current Tailwind their vendor `@source` line is
**inert** — their compiled `styles.css` carries library utilities today only
because it was compiled in an environment/version where the scan happened to
see the tree. Same input, different CSS per environment: exactly the class of
silent breakage a library should make impossible.

The other two mechanisms both converge on the same idea — get the class
strings into a TRACKED PLAIN FILE the scanner can read — but each consumer
re-derives the generator, the staleness guard, and the multi-module resolution
(the library is 7 Go modules; Go strips nested modules from the parent's
cache dir, so naive module-cache paths miss `utils/`, `icons/`, `htmx/`,
`datastar/`).

### Existing library-side artifacts

- `templates/app.css` + `templates/custom.css` — consumer entry point +
  `.tc-*` classes. Solves CUSTOM-class delivery, not utility-class scanning.
- `templates/styles.css`, `templates/templ-components-theme.out.css` —
  release.sh-compiled artifacts (theme layer + custom classes). They do NOT
  contain the utility classes components emit; importing them is not a
  substitute for scanning.

## Decision

**The library ships a release-generated class inventory file;
vendor-`@source` is demoted to a documented, explicitly-fragile variant;
compiled-whole-library CSS stays rejected.**

### 1. `templates/templ-components-classes.txt` — the blessed default (T2)

One plain text file containing the concatenation of every class-bearing
library source (all `.templ` + class-carrying `.go` across all 7 modules —
`utils/svg`, `icons/icon_paths.go`, wire attribute dialects, the works),
generated by a `scripts/gen-class-inventory.sh` step wired into
`scripts/release.sh` and guarded by a freshness test in the same family as
`TestCSSFreshness` (regenerate → byte-compare; fail on drift so the file can
never lag a release).

Consumer adoption — three lines, version follows `go.mod` because the file
rides the module:

```bash
cp "$(go list -m -f {{.Dir}} github.com/larsartmann/templ-components)/templates/templ-components-classes.txt" internal/css/
```

```css
@import "tailwindcss" source(none);
@source "./templ-components-classes.txt";
@source "./**/*.templ";   /* the consumer's own sources */
```

Properties this buys (each maps to a real failure above):

- **Environment-independent**: a tracked plain file; no `.gitignore`
  semantics, no vendor tree, no Nix-sandbox divergence (dnsblockd's cure,
  library-owned).
- **Toolchain-independent**: the file is generated ONCE per release with the
  library's pinned Tailwind lane knowledge, not re-derived per consumer with
  whatever toolchain/env they have.
- **No Go toolchain in the CSS pipeline**: the nsfw constraint (their Nix
  CSS build needs no module cache) holds — the copy step is a consumer build
  step, the scan needs only the copied file.
- **Multi-module-complete by construction**: the generator walks all 7
  modules; consumers cannot get this wrong.

Trade-off accepted: the inventory scans ALL library classes (no per-file
curation, so emitted CSS is larger than nsfw's curated mirror). Consumers who
need minimal CSS may still curate — but they own that curation explicitly
instead of implicitly depending on vendor-pruning. Revisit only if a consumer
demonstrates the size delta matters (YAGNI until then).

### 2. Tracked-source `@source` — the monorepo variant

When the library sources are CHECKED OUT inside the consumer's Tailwind scan
root (monorepo, git submodule that is committed, or a vendored-and-committed
tree), direct `@source` on the real `.templ` files remains blessed — it is
the same mechanism the demo uses (`examples/demo/demo.css`
`@source "../../**/*.templ"`). The ADR's requirement is one word: **tracked**.
Gitignored vendor trees are NOT this variant; they are the broken case.

### 3. Rejected: shipping compiled whole-library CSS

Pre-compiling every utility the library can emit (`bg-blue-600`,
`dark:` pairs, `peer-checked:` chains, `@container` variants) into one
importable CSS file would remove scanning entirely — at the cost of (a)
emitting ALL classes for every consumer (no pruning by adopted surface),
(b) duplicating Tailwind's variant machinery outside the consumer's own
compile (their `@theme` overrides still cascade via CSS variables, but
variant-DENSITY decisions freeze at library release time), and (c) a
second, competing delivery story. The inventory file keeps the consumer's
compiler the single source of CSS truth. Revisit only alongside a future
"CSS-on-rails" distribution demand.

## Consequences

- **T2 scope** (TODO #399): generator script + release.sh wiring +
  freshness guard + `docs/tailwind-v4-adoption-guide.md` section rewrite
  (lead with the inventory file) + consumer migration notes (nsfw: delete
  mirror + sync script; dnsblockd: delete generator, keep filename as a
  symlink or switch `@source`; DiscordSync: replace the inert vendor line —
  their badges likely already depend on a stale compiled artifact).
- **ADR-0044 interplay**: post-T1 the inventory naturally carries `accent-*`
  classes; no separate handling.
- **TestCompiledCSSInventory**: the file is deliberately NOT `.css` (it is a
  scan corpus, not styles) — the compiled-CSS guard's set is unchanged; the
  new freshness guard owns it.
- **`cmd/tc` starter** (`tc init`): T2 adds the copy step to the scaffolded
  build docs so new consumers start on the blessed path.
- **Website docs**: the Tailwind adoption guide gets the three-line
  quickstart; the comparison matrix's CSS story stays honest ("scan corpus
  shipped in the module").

| ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| dnsblockd: "Tailwind v4.3 never scans .gitignore'd paths… different CSS depending on the environment" | Tracked plain file — no gitignore semantics anywhere in the path                                                    |

| nsfw: "no vendor/ directory, no Go toolchain, no module cache" in the CSS pipeline                    | Copy-then-scan; only the copy step touches Go                                                                       |
| nsfw: multi-module cache stripping                                                                    | Generator walks all 7 modules once, centrally                                                                       |
| DiscordSync: inert vendor `@source` under current Tailwind (gitignored `vendor/`)                     | Inventory default makes the fragile line unnecessary; tracked-source variant documented with its requirement stated |
