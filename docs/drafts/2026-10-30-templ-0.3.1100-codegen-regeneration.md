# Draft — templ-components issue (2026-10-30)

## Proposed title

templ v0.3.1100 removed `templ.ResolveAttributeValue` — regenerate the committed codegen to unblock the security bump

## Body

## Problem

templ-components cannot bump `github.com/a-h/templ` past v0.3.1070 without a full codegen regeneration, and the reason is a deliberate removal, not an accident.

templ [v0.3.1100](https://github.com/a-h/templ/releases/tag/v0.3.1100) (2026-10-26) **removed rather than deprecated** three runtime helpers that pre-0.3.1100 codegen emitted calls to: `templ.ResolveAttributeValue`, `templ.RenderAttributes`, and `templ.JoinURLErs` ([ADR-0004](https://github.com/a-h/templ/blob/main/docs/adr/0004-attribute-sanitization.md)):

> Removing them means that code generated by an earlier version of templ that calls them fails to compile, so that the vulnerability is fixed by regenerating.

This repo's committed generated code still calls the removed helper. At `1852b86e`, `utils/svg/svg_templ.go:57`:

```go
templ_7745c5c3_Var3, templ_7745c5c3_Err = templ.ResolveAttributeValue(templ.CSSClasses(templ_7745c5c3_Var2).String())
```

The helper still exists in the pinned generation toolchain (`templ@v0.3.1070` `runtime.go:697`), and `go.mod` pins `github.com/a-h/templ v0.3.1020` — so the build is green today. But the moment templ moves to ≥ v0.3.1100, this file (and every other committed `*_templ.go` generated by the old codegen) stops compiling.

## Why it matters

The removal is the fix delivery mechanism for a security class: code generated by older templ does not sanitize spread attributes or URL-valued attributes (`<iframe src>`), and the JS template literal escaping + mixed-case attribute tightening in v0.3.1100 ride the same release. As long as templ-components pins ≤ v0.3.1070, every consumer inherits none of it.

Downstream effect, verified: `go-credentials-store` (consumer, templ-components v1.25.0) has its templ v0.3.1100 bump (the only security-bearing dependency task in its backlog) blocked on exactly this.

## Proposed path

1. `go get github.com/a-h/templ@v0.3.1100`
2. Regenerate every `*_templ.go` with the new codegen (`templ generate` per repo canon)
3. Fix any compile fallout from the new generator output (new codegen emits `templruntime`-scoped attribute handling, so the removed-helper calls disappear)
4. Tag a templ-components release; consumers bump templ + templ-components together

No upstream ask: a-h/templ's removal is documented and intentional (ADR-0004). The action item is entirely here — regenerate and release.
