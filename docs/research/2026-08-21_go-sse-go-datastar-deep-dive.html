00Summary

templ-components deliberately depends on exactly one module of the three-module SSE stack: github.com/larsartmann/go-datastar/static — the zero-dependency module that embeds the Datastar JS runtime. Neither go-sse (transport: Stream, Broadcaster, Replay) nor go-datastar root (protocol: Patch values, Response builder, MemoryStore) is a dependency. That is the correct call — ADR-0030 keeps consumer dependency graphs clean and the module DAG strict.

But "not importing the protocol library" only works if everything the library emits — attributes, wire format, event names, CSP guidance — matches what the pinned runtime actually accepts. Auditing against the pinned v1.0.2 bundle showed it did not: the demo SSE stream had never delivered a single event, and SSEErrorHandling listened for an event the runtime has never dispatched. All eight findings are fixed in this session and pinned by tests.

The bottom line The pinning strategy was already "to the max" (version derived from static.Version at compile time — CDN URL and embedded bundle cannot drift). The runtime integration was at 0% until today: every emitted protocol detail is now verified against the pinned bundle, with wire-format and lifecycle-event regression tests. Remaining upside is optional real-runtime E2E in CI via go-datastar's datastartest.

◆What's already leveraged well

+
Compile-time version pin, zero drift possible DatastarVersion1_0_2 = DatastarVersion(static.Version) (datastar/version.go:21). The CDN URL and any self-hosted bundle served from static.Bytes() are the same bits by construction.
+
Zero transitive dependencies honored go-datastar/static's go.mod requires nothing (stdlib only), so the datastar module adds no consumer deps — the ADR-0030 promise is structurally enforced, not just documented.
+
Self-host path first-class SDKScriptProps.Src (datastar/sdk_script.go:17) plus documented static.Bytes() serving in the recipe and package godoc; identical pattern to HTMX self-host.
+
Attribute surface matches the runtime parser data-init, data-on:click, data-indicator:<name>, data-show="$signal" all verified against the v1.0.2 bundle's attribute parser (plugin name split on the first colon; signal access via $name rewriting). The @get/@post/@put/@patch/@delete action helpers match the five registered runtime actions.

01Findings (all fixed this session)

Misused · was active harm · FIXED

SSEErrorHandling listened for an event the runtime never dispatches

datastar/sse_error_handling.templ (before) · no datastar-sse-error exists in the v1.0.2 bundle

The runtime reports the fetch/SSE lifecycle exclusively on the document-level datastar-fetch event: detail.type is one of started, finished, error (HTTP status ≥ 400, status in detail.argsRaw.status), retrying, or retries-failed (gave up after 10 attempts, exponential backoff). The old handler also read detail.message/detail.statusText — fields that do not exist; the real detail shape is {type, el, argsRaw}. The component was 100% inert. 

// Before — never fires:
document.addEventListener('datastar-sse-error', function(evt) {
    var reason = detail.message || detail.statusText || '...';

// After — the real lifecycle event:
document.addEventListener('datastar-fetch', function(evt) {
    var detail = evt.detail || {};
    if (detail.type === 'error') {            // HTTP-level failure
        var status = (detail.argsRaw || {}).status;
    } else if (detail.type === 'retries-failed') { // reconnects exhausted
        // toast; stream is dead until the action re-runs
    } // 'retrying' → console only (would spam up to 10 toasts)
Recommendation (applied) Terminal failure states toast + announce via aria-live; transient retrying stays console-only. A regression test asserts the dead event name never returns; a golden snapshot pins the emitted script.
Misused · demo stream never worked · FIXED

Demo SSE endpoint: four independent wire-format bugs

examples/demo/main.go (before: handler at the mux registration) · verified against the v1.0.2 bundle SSE parser

(1) Format strings ended in \\n — literal backslash-n text, so the stream contained no blank line and the browser dispatched zero events. (2) The event name datastar-merge-fragments was removed in Datastar v1.0; only datastar-patch-elements / datastar-patch-signals have registered handlers. (3) The id-less fragment was dropped: the default outer mode matches incoming root elements by getElementById. (4) The server's WriteTimeout: 10s raced the 5th tick at exactly t=10s. 

// Before (one of the broken writes — literal "\n" text):
fmt.Fprintf(w, "event: datastar-merge-fragments\ndata: <div ...>\\n")

// After — v1 wire format, keyed datalines, real newlines, blank terminator:
event: datastar-patch-elements
data: selector #datastar-live-content
data: mode inner
data: elements <p ...>SSE update #1 — streamed at 12:00:02</p>

// Plus: http.NewResponseController(w).SetWriteDeadline(time.Time{})
// (SSE outlives the global WriteTimeout), X-Accel-Buffering: no,
// and streaming until client disconnect with write-error bail.
Recommendation (applied) New examples/demo/sse_test.go pins the exact bytes of writeDatastarPatch and exercises the handler over HTTP (headers, framing, first event). The mux was extracted into newMux() so endpoints are testable — the bug shipped because nothing could reach them.
Misused docs · security-relevant · FIXED

Recipe claimed Datastar needs no 'unsafe-eval' under CSP

docs/recipes/datastar-integration.md (CSP section)

The runtime compiles every data-* expression with the Function() constructor (verified in the bundle: Function("el", "$", "__action", "evt", ...)). CSP classifies that as eval — without 'unsafe-eval' all expression attributes silently fail. Consumers copying the old snippet would break their Datastar app while believing it was sandboxed. 

# Before — wrong:
script-src 'self' https://cdn.jsdelivr.net;

# After — truthful:
script-src 'self' https://cdn.jsdelivr.net 'unsafe-eval';
# 'unsafe-inline' still NOT needed (external module + nonced inline scripts)
Misused docs · examples threw at runtime · FIXED

Documented patch pattern omitted WithSelector

datastar/doc.go, live_region.templ, live_region.go, docs/recipes/datastar-integration.md

All godoc/recipe examples showed PatchElementsTempl(...) without a selector — the runtime throws PatchElementsExpectedSelector for any non-default mode without one, and the default outer mode drops id-less fragments. Every example now pairs WithSelector("#id") with WithModeInner() and gives the target element an id.

Partially used · dead helper · FIXED

datastarCDNOrigin existed but was never called

datastar/version.go:62 · datastar/sdk_script.templ

The preconnect-origin helper (with its own tests) was a ghost system: layout.Base preconnects for HTMX, but SDKScript did not. It now emits <link rel="preconnect" crossorigin> for CDN loads (skipped when self-hosting via Src).

Edge case · always-visible spinner · FIXED

Indicator with empty Signal rendered data-show="$"

datastar/indicator.go (indicatorSignalExpr)

$ alone is the signals object — always truthy — pinning the spinner visible forever. Empty Signal now degrades to data-show="false" (hidden), matching the library's graceful-degradation convention.

02Explicitly not gaps (by design)

These go-datastar / go-sse capabilities are not missed opportunities for the library itself. Importing them would violate the dependency policy (allowed: templ, tailwind-merge-go, go-error-family for errorpage only) and the module DAG — and would add go-sse + go-branded-id + go-error-family to every consumer's graph for a UI library that only needs to emit correct markup:

Capability Module Verdict
Stream, Heartbeat, Broadcaster[T], Replay/EventStore go-sse Consumer-side — documented in the recipe, never a library dep
Patch interface, Response builder, MemoryStore, ReadSignals, GetSSE/PostSSE go-datastar root Consumer-side — godoc points consumers at it (go get their own)
ssetest / datastartest E2E helpers both Candidate for CI of the demo (see opportunities) — not a runtime dep
SRI integrity hashes — Datastar publishes no official SRI; documented in version.go — self-host to get integrity
